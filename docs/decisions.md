## 1. 写真は、縮小・圧縮した `Data` だけを保存する

- 決定: メインとサムネイルの2種類を、JPEG 品質 0.5 で保存する。元画像は保存しない
- 他の案: 元画像だけを保存して、表示のたびに縮小する
- 理由: 実測で、1日1件・1年あたり約 83.5MB(元画像を残すと約 1.2GB)。家族に見せて、画質に違和感がなかった。品質 0.5 は、AI(Claude Code)が無難な値として挙げたものを、実測で確かめて採用した
- 未確認: 縦向き写真の向き、表示の負担
- 詳細: `verification.md` 1章、`design.md` 5章

## 2. 画面の幅は CreateView 自身で測る

- 決定: `CreateView` の中で、`.onGeometryChange` を使って幅(pt)を測り、`@State` に入れる。`UIScreen.main` は使わない
- 変更の経緯(2026-11-15): 最初は、親の View(`ContentView`)で幅を測り、引数で `CreateView` に渡す形にしていた。実機で、`CreateView` が受け取る幅が 0 になり、写真の縮小が `shrinkSize` で失敗した。親は、ボタンを押す直前に、正しい値(402)を持っていたのに、`CreateView` の中では 0 だった。`CreateView` が自分で測る形に変えると、正しい幅が取れた
- 原因: 特定できていない。予想は、「シートを開くと、親が測っている幅が 0 になる」こと。確かめていない(`open-issues.md`)。公式ドキュメントには、`onGeometryChange` と `fullScreenCover` の、呼ばれるタイミングの記述がなかった
- 学んだこと: 「親で測って渡す」設計は、渡す時点の値が正しいことに依存する。「使う場所で、自分で測る」と、タイミングの問題が起きない。幅を測ることは、フラグで一回だけにしなくてよい(`onGeometryChange` は、値が変わったときだけ呼ばれる)
- 他の案: `UIScreen.main`(グローバルで簡単。試作ではこれを使った)
- 理由: 非推奨のため。グローバルな変数だと、どこからでも書き換えられ、ウィンドウが複数あると値が決まらない
- つまずいたこと
  - 試作では、`UIScreen.main` で動き、Xcode に警告も出なかった。実装のときに調べ直して、初めて非推奨だと知った。動いていても、非推奨かどうかは、公式の資料で確かめる
  - 中身が空の `VStack` に付けると、幅が 0 になった。画面いっぱいに広がる `ScrollView` に付けると、取れた(402pt)
- 詳細: `design.md` 7章 `screenWidthPx`

## 3. 「追加」ボタンは、`overlay` で右下に置く

- 決定: `.overlay(alignment: .bottomTrailing)` を、画面いっぱいの View に付ける
- 他の案
  - `ZStack` と `Spacer` で位置を組む(力技で、組み方が複雑になる)
  - `.safeAreaInset`、ツールバー、UIKit(詳しい比較はしていない)
- 理由: `Spacer` なしで、位置だけを指定できる。`overlay` は、付けた View の大きさが基準なので、画面いっぱいの View に付ければ、画面の右下になる
- 残っていること: 見た目(純正のボタンに近づけるか)は、機能がそろってから調整する

## 4. 失敗は `throws` で表し、エラーの型を2つに分ける

- 決定
  - `ImageResizeError`: 縮小・圧縮の関数が投げる4種類の失敗(`Logic/` に置く)
  - `ImageError`: アラートに出す失敗。`ImageResizeError` を包み、写真の読み込みの失敗も持つ(画面側に置く)
- 他の案: `nil` を返す(理由がわからない)。失敗したら、元の大きさで返す(「元画像は保存しない」と食い違う)
- 理由
  - `Logic/` は、画面に依存しない。利用者向けの文言は、画面側の事情なので、`ImageError` に持たせた
  - `message` は、`switch` に `default:` を付けず、全ケースを書く。新しいケースを足して、メッセージを書き忘れると、ビルドエラーで気づける
- 未確認: 写真をすばやく選び直したときの `CancellationError`
- 詳細: `design.md` 7章「画像のエラー処理」

## 5. 小さい画像は、拡大しない

- 決定: 長い辺が `px` 以下なら、縮小を飛ばす。圧縮は、必ずかける
- 他の案: そのまま(拡大される)。元のデータを、そのまま返す(圧縮を飛ばして、形式がそろわない)
- 理由: 拡大しても、画質は良くならず、データが増えるだけ。テストを書いて、拡大されることに気づいた
- 詳細: `design.md` 7章 `shrinkAndComp`、9章
