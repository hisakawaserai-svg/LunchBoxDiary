- [ ] 親の View で測った幅を、引数で `CreateView` に渡すと、`CreateView` で 0 になった(実機で発見、2026-11-15)。`CreateView` が自分で測る形に変えて、直った。残り: 原因の確認。予想は「シートを開くと、親が測っている幅が 0 になる」。確かめ方の案: 親の `onGeometryChange` が、`CreateView` を開いたあとに、また呼ばれて 0 になるか、コンソールで見る。ボタンを押す直前の値は 402、`CreateView` の `onAppear` では 0 だった

- [x] `detailPx()` の画面の倍率は、`@Environment(\.displayScale)` に置き換えた(試作で確認、2026-11-10)
- [ ] 試作の `DayView` は、`lunches.first` を使っている。`@Query` は日付順なので、同じ日の中では、時刻の順。仕様の「タイトル順」と違う。`sorted` でタイトル順にそろえる必要がある
- [ ] 親の View の幅が 0 のとき(最初のレイアウトの前)に、縮小が走らないか。`preparingThumbnail` に 0 を渡すとどうなるか

- [ ] `shrinkAndComp` が、失敗したときに元の画像を返す(「元画像は保存しない」方針と食い違う)。失敗時の扱い

## フレーム

- [ ] 10種類の形とデザイン(家族に見せて決める。モックの「フレームの案10種類」。シマエナガ、ポラロイド風は家族のリクエスト)
- [ ] シマエナガの絵の用意(自分で描くか、素材を使うか。素材なら利用規約。GitHub に公開することも考える)
- [ ] 10種類のフレームを、1か月の期間で作れるか。作る順番(家族のリクエストを先にする、など)
- [ ] フレームのデザインを、誰がどう用意するか。家族の感想: 「もっと全然違う人がデザインしたのがいい。形も別で。前のものに貼り付けただけに見える」(案は、どれも同じ配置の土台に、輪郭や飾りを足しただけだった)
- [ ] フレームの作り方: コードで形を描く(`Shape` や `Path`)か、画像の素材を使うか。デザインの自由度が高いほど、画像素材に寄る
- [ ] フレームの範囲: 縁だけか、背景や飾り、タイトルの文字まで含む「カード全体のテーマ」か(家族の参考画像は、カード全体のテーマだった)。モックの「テーマカードの案10種類」(枠・飾り・背景 + タイトル書式のセット、2色ずつ)を家族に見せて決める
- [ ] テーマカードの読みやすさ。モックで使ったルール: 日本語は日本語フォント、英字の筆記体は日付や飾りだけ、色の上の文字は明るさで白/黒を自動選択、写真の上の文字は白い板を敷く。実装できるか(色の明るさの計算を自作する必要がある)
- [ ] 家族の反応(第1弾): 気に入ったのは「ストライプ」「おちば」「ポラロイド」と、最初の「ほしの枠」。日付の見せ方も好評。「おちば」の「Autumn bento」は、秋しか使えないので不要。他は別案がほしい → 第2弾(横長カード、新案6つ)を作った。家族の感想待ち
- [ ] 家族の反応(第2弾): デフォルトは「ほしの枠」にする予定(決定。家族の言葉)。気に入った: くも、ノート、ほし空(+前回のストライプ、おちば、ポラロイド)。ギンガム・おはなは外す。シマエナガは、自作のマスコット(`BirdMascot.tsx`)の図形で作る。ストライプのタイトルのフォントは合わないので変更 → 第3弾(8種類)を作った。あと2つで10種類
- [ ] 日付の見せ方を、テーマごとに複数バージョン(「2026.11.03」「Nov 3」「11月3日(火)」など)にしたい(家族の要望)。フォントはテーマに合わせる。持ち方: ユーザーが選べるのはテーマと色だけ(決定)なので、日付の書式は保存せず、テーマごとに固定にする。複数バージョンがほしい場合は、別のテーマとして作る。家族に、この方針で足りるか確認する。日付の書式は、テーマごとに選べる種類が違う
- [ ] フォント(家族の指摘: 混ざって合わない。自分の希望: Google のフォントはやめたい): iPhone に最初から入っている日本語フォント3つ(ヒラギノ丸ゴ ProN W4、ヒラギノ明朝 ProN W3/W6、ヒラギノ角ゴ(Hiragino Sans)W3〜W8)だけにした。テーマごとに1つで、タイトルも日付も同じ。確認元: Apple の「Fonts for Apple platforms」。Yu Gothic・Yu Mincho などはダウンロード式で、標準では入っていない。メリット: ライセンスの心配が要らない、ファイルを足さなくてよい。デメリット: 3種類しかない(違いは太さ・大きさ・字間・色で出す)、React Native(Android)へ移すと使えない(代わりのフォントが必要)

- [ ] この Linux の環境では、ヒラギノを表示できないので、モックのレイアウト確認は近い字体で行った。実機(Mac・iPhone)での見え方は未確認
- [ ] お弁当の写真の窓は、全テーマで同じサイズ(横長 5:3、モックでは 240×144)にした。カレンダーのマスの写真も同じ(40×42)。この比率で、実際の写真(4:3 など)をどう収めるか(上の項目)
