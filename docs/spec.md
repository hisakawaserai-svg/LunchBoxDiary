# お弁当日記 要件定義・仕様書

最終更新: 2026-11-08

この仕様書には、確定したことだけを書く。未決のことは `open-issues.md` に置く。作り方(設計)は `design.md` に書く。

## 1. 要件定義

### 課題
- 作ったお弁当を、思い出として残したい
- 元々使っていた料理保存アプリがサービス終了し、そこに保存していたお弁当が見られなくなった。お弁当を残す場所が、いま無い

### 対象ユーザー
- お弁当を作っている人
- 実在のユーザー: 家族(Android を使っている)

### 目的
- ユーザーが、お弁当を写真に撮って記録し、過去のお弁当を振り返って確認できる
- 記録の対象はお弁当のみ。ご飯全般・カロリー・栄養は対象外

### 要望と機能

| 家族の要望 | 満たす機能 |
|---|---|
| カレンダー式で、お弁当を日記のように保存・確認したい | ホームの月カレンダー(2・3章) |
| 誰向けに作ったかを、保存・確認したい | 「誰に」の項目(4章) |
| あとから、タイトル・メモ・写真などを修正・編集・削除したい | 作成・編集の画面、削除(2章) |
| 写真の周りを、可愛いフレームで飾りたい。形がいろいろあるとよい。5つ以上ほしい。シマエナガと、ポラロイド風がほしい。自分で作るのではなく、用意してほしい。タイトルの書式も変えたい(フレームとセット) | フレーム(5章)。10種類ほど用意する(色だけの枠と、形や飾りがいろいろな枠) |
| イベント名を残して、あとで探したい(タグは不要、メモでよい) | イベント名の項目(4章) |
| お弁当を探したい。イベント名でも絞り込みたい | 探す機能(検索・フィルター)。イベント名と「誰に」で絞り込み(カレンダーとリストの両方)。日付では探さない |

- 家族の要望にはなく、こちらで足した機能: ホームのリスト表示(カレンダーとの切り替え)

### 動作条件
- 対象 OS: iOS 17 以上(SwiftData を使うため)
- 家族は Android のため、Swift 版は家族の端末では動かない。Swift 版は iPhone で動作確認する
- 開発方針: Swift で作り、のちに React Native へ移行して、家族に渡す予定。公開方法は検討中
- 期間の目安: 1ヶ月。機能は絞る
- 記録は端末の中に保存する。アプリを消すと、記録も消える

## 2. 画面構成

タブバーは使わない。

| 画面 | 内容 |
|---|---|
| ホーム | 月のカレンダー。ボタンでリスト表示に切り替える(同じ画面の中) |
| 詳細 | シートで表示する。上にフレーム付きの完成カード、下にイベント名・メモ・操作ボタン。その日に複数件あるときは、横にスワイプして切り替える。カードの写真を押すと、写真の全体を見られる(カードの窓では、写真の端が切れることがあるため。決定、2026-11-11) |
| 作成・編集 | 1画面で兼用する。上に完成プレビュー、下に入力欄 |

- 完成カードは、詳細と、作成・編集のプレビューで同じ部品を使う
- 作成・編集の入力途中の内容は、一時的な値として保持する。保存したときに、記録へ書き込む
- ホームの右下に、記録を追加するボタンを置く(家族は右利き)。カレンダーと重ならないよう、ボタン分の余白を確保する
- 作成画面を開いたときの日付は、今日にする。あとから変更できる
- 月の切り替えは、横スワイプと、矢印ボタンのどちらでもできる
- 記録を削除するときは、確認のアラートを出してから削除する
- リスト表示では、1日に複数件ある日も、すべて表示する
- リストは、月ごとに見出し(区切り)を付ける(決定、2026-11-11)
- リストの並び順は、初めは古い順(上が古い)。切り替えられる(決定、2026-11-11)。リストを開いたとき、いま見ていた月の月初の位置まで移動する(決定。仮の方法は設計書の11章)
- お弁当を探す機能(検索・フィルター)を付ける。家族の要望。イベント名と「誰に」で絞り込める。カレンダーでも、リストでも使える(家族の要望。決定、2026-11-11)。タイトルでの検索は、時間があれば付ける(未決)。メモは、検索の対象にしない。日付では探さない(検索・絞り込みに入れない。リストの月の見出しへの移動で代わりにする。決定、2026-11-11)

## 3. ホーム(カレンダー)の動き

- 1日に、複数件の記録を持てる
- 記録がある日のマスには、その日の先頭1件の写真を、フレーム付きの小さいカードで表示する(家族の要望。マスのカードは縦長、詳細・編集のカードは横長)
- 「先頭1件」は、日付が同じ記録のうち、タイトル順で一番前のもの。作成日時の項目は持たない
- マスには、タイトルを表示しない。写真とフレームだけにする(決定、2026-11-10。試作で、狭いマスでは文字が折り返して崩れたため)
- その日に2件以上あるときは、マスに件数のバッジを付ける
- 記録がない日のマスは、日付だけを表示する
- 日付を押したとき
  - 記録がない日: 何もしない
  - 記録がある日: 詳細シートを開く。複数件あるときは、横にスワイプして切り替える

## 4. 1件の記録が持つ項目

| 項目 | 必須/任意 | 内容 | 備考 |
|---|---|---|---|
| 写真 | 必須 | お弁当の写真 | `Data` 型。SwiftData の `@Attribute(.externalStorage)` で保持する |
| タイトル | 必須 | 料理名 | |
| 日付 | 必須 | 作った日。過去の日付も選べる | 日単位で扱う |
| メモ | 任意 | ひとこと | |
| 誰に | 任意 | 誰に向けたお弁当か。1人だけ選ぶ | 別モデルを `@Relationship` で参照する |
| イベント名(タグから変更) | 任意 | 運動会など。1件の記録に、複数付けられる(決定、2026-11-11)。家族の要望は「タグは不要、イベント名が欲しい」 | 別テーブル(`Event`)に持ち、「誰に」と同じく、登録した名前から選ぶ(決定)。検索・フィルターに使う。登録・編集の画面は検討中 |
| フレーム | 必須 | 見た目の飾り。別テーブルにはしない。記録が持つのは、テーマ(`enum`)と色(16進数の文字列)だけ。フレームの見た目は、`struct` と `enum` で作る。ユーザーが選べるのは、テーマと色だけ | 5章を参照 |

- 「誰に」とイベント名は、色を持たない。色を持つのはフレームだけ。カレンダーのマスの色は、フレームの色で決まる
- 元画像は保存しない。保存するのは、縮小した写真(拡大表示用)と、サムネイル

## 5. フレーム

- フレームは、アプリが用意したものから選ぶ。ユーザーが形を作ることはできない
- 用意するのは、色だけのフレームと、形がいろいろなフレーム(ギザギザなど)。形が違うフレームは、フレームごとにデザインを用意する
- 色は、`ColorPicker` で選べる。保存は文字列(16進数)
- 飾りの配置は、あらかじめデザインしたもので固定する(乱数では決めない)
- タイトルの書式(フォント、大きさ、色、位置)は、フレームとセット。フレームごとに決まっていて、ユーザーが書式だけを別に選ぶことはない
- 用意する数: 家族は5つ以上を希望。10種類ほどを目標にする
- 家族のリクエスト: シマエナガのフレーム、ポラロイド風のフレーム
- 初期のテーマ(デフォルト)は「ほしの枠」にする
- 日付の見せ方は、テーマごとに複数のバージョンを用意し、フォントはテーマに合わせる(家族の要望)。持ち方は検討中
- 現在のテーマは8種類(ほしの枠、ストライプ、おちば、ポラロイド、くも、ノート、ほし空、シマエナガ)。家族の希望(5つ以上)は満たしている。残り2つは、追加するときに決める。具体的なデザインは、まだ決めていない
- 以前の「星などのマーク」は、フレームのデザインの一部にするか、別にするかを、検討中
